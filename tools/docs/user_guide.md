# Руководство пользователя

Документ написан для человека, который пользуется устройством вместе с
кошельком Feather, а не пишет для него код.

---

## Прежде чем начать

**Устройство не прошло аудит безопасности и не проверено на реальных
средствах.** Пока не пройдена проверка в тестовой сети (stagenet), считайте
устройство демонстрационным и не храните на нём деньги, которые жалко
потерять.

Что нужно иметь:

- само устройство (ESP32-S3 с экраном) и USB-кабель с данными;
- компьютер с **Feather Wallet** и программой `mwlink_gui.py`
  (`tools/mwlink`, нужен Python 3 и `pip install pyserial hidapi`);
- бумагу и ручку — seed-фразу записывают на бумаге, не в телефоне.

---

## 1. Как устроена работа

Устройство никогда не подключается к интернету. Оно хранит ключи и делает
три вещи, каждую — только после подтверждения на своём экране:

1. по файлу выходов Feather считает **key images** (синхронизация баланса);
2. по неподписанной транзакции Feather делает **подписанную**;
3. по запросу ПК отдаёт **адрес** или данные для **view-only кошелька**
   (адрес и private view key).

```
   Feather (view-only)          mwlink_gui           Устройство
         |                          |                     |
   export outputs  --> папка --->   |  --- файл --->      |  вы подтверждаете,
         |                          |                     |  устройство считает
   import key images <- папка <---  |  <-- keyImages ---  |
         |                          |                     |
   create tx       --> папка --->   |  --- файл --->      |  вы сверяете сумму,
         |                          |                     |  адрес, комиссию
   submit          <-- папка <---   |  <-- signed tx ---  |  и подписываете
```

Программа на ПК только переносит файлы и показывает журнал устройства.
Seed-фраза, passphrase и private spend key никогда не покидают устройство.

## 2. Включение: игра и пароль

При включении (и после каждой блокировки) устройство выглядит как обычная
игра **«Сапёр»**: касание открывает клетку, долгое касание или режим **F**
ставит флажок, **↻** начинает новую игру.

**Вход в кошелёк:** подорвитесь на мине, затем **трижды быстро (за 2
секунды) коснитесь взорванной мины** (клетка с крестиком). Другие касания
сбрасывают счёт.

**Первое включение: ключ в чипе.** Если в чипе ещё нет секретного ключа
(eFuse), устройство сначала предложит записать его — до пароля. Без этого
ключа устройство не работает: «Отмена» возвращает к игре. Ключ случайный,
записывается один раз и навсегда в старший свободный блок ключей eFuse
(обычно `BLOCK_KEY5`; номер блока показан на экране) и не читается даже
прошивкой — только используется. Запись **необратима**: два подтверждения и
ввод кода. Состояние блоков — **Настройки → eFuse key blocks**.

Дальше устройство спросит **пароль устройства**:

- при **первом включении** его нужно придумать (от 8 до 64 символов) и
  ввести дважды — без пароля пользоваться устройством нельзя. На пароль только
  из цифр, из одного повторяющегося символа или вида `abcdefgh` устройство
  предупредит: такой пароль подберут, если устройство украдут. Пароли из 4–7
  символов, заданные прежними прошивками, по-прежнему открывают устройство,
  но новый пароль (Настройки → пароль) должен быть не короче 8 символов;
- потом — вводить при каждом входе. После трёх ошибок каждая следующая
  попытка откладывается (2, 4, 8 … секунд, до 10 минут); задержка
  сохраняется и после перезагрузки.

Пароль вместе с ключом внутри чипа шифрует все seed-фразы. «Отмена» на
экране пароля возвращает к игре.

## 4. Создание кошелька

Кошельки → **Создать кошелёк**.

1. **Имя** кошелька.
2. **Формат seed-фразы**: Monero legacy (25 слов) или Polyseed (16 слов,
   хранит дату создания — restore height не нужен).
3. **Источник случайности**: аппаратный ГСЧ или 100 бросков кубика.
4. **Запишите слова на бумагу** — по порядку, с номерами. Устройство не
   покажет их второй раз.
5. **Проверка**: устройство попросит несколько слов по номерам.
6. **Passphrase** (см. ниже) — ввести дважды или явно выбрать «Без
   passphrase» с двумя подтверждениями.
7. Устройство покажет **адрес** — сверьте его потом с Feather.

### Passphrase: два кошелька на одну фразу

Passphrase — дополнительное слово к seed-фразе. Если вы его задали, у
записи на устройстве **два кошелька**:

| При открытии введено | Открывается |
| :--- | :--- |
| ваш passphrase | кошелёк с passphrase |
| пусто | кошелёк той же фразы без passphrase |
| что-то другое | «Неверная passphrase» — устройство проверяет её |

Устройство не хранит сам passphrase, только короткую контрольную метку в
зашифрованной записи. Кошелёк, созданный без passphrase, открывается сразу,
без вопроса. В списке кошельков записи с passphrase помечены `*`.

В Feather такой кошелёк восстанавливается той же фразой, если в мастере
восстановления указать passphrase в поле seed offset (смещение seed).
Устройство использует ту же схему, что Feather и Monero CLI
(`cryptonote::decrypt_key`), для 25 и для 16 слов.

**Забытый passphrase не восстанавливается.** Запишите его отдельно от
seed-фразы.

## 5. Импорт кошелька

Кошельки → **Импортировать кошелёк** → 25 слов, 16 слов или ключи.

1. Имя, затем слова: первые буквы → выбор из списка. Если контрольная сумма
   не сошлась, устройство подсветит слово, с которого проверять.
2. Passphrase — как при создании: пусто, если его не было.
3. Для 25 слов — restore height (номер блока; 0, если не знаете).
4. Сверьте адрес с Feather.

Импорт по ключам (spend + view или view-only) создаёт кошелёк без варианта
с passphrase.

**16 слов из Cake Wallet / Cupcake.** Там passphrase шифрует саму фразу
(флаг «encrypted» в polyseed), а не применяется как seed offset. Устройство
определяет формат по фразе само: для такой фразы оно сообщает «Фраза
зашифрована passphrase (Cake Wallet / Cupcake)», и passphrase становится
обязательной — без неё кошелёк не открывается. Ошибку в passphrase polyseed
обнаружить не может: получится другой кошелёк, поэтому сверьте адрес с
Cupcake. Новые кошельки устройство всегда создаёт в формате Feather
(фраза не зашифрована, passphrase — seed offset). MoneroPunkSigner тоже
восстанавливает такие фразы: при вводе 16 слов он спросит их passphrase.

## 6. Меню кошелька

Кошельки → выберите кошелёк → (passphrase, если есть). Заголовок — имя
кошелька, под ним вариант («без passphrase» / «с passphrase») и состояние
связи: **«Готов к приёму файлов с ПК»**.

| Пункт | Что делает |
| :--- | :--- |
| Адрес | адрес текстом |
| Private view key | ключ текстом, после предупреждения |
| Переименовать | новое имя |
| Удалить кошелёк | после ввода показанного числа; стираются запись и кэш key images |
| Закрыть кошелёк | ключи стираются из памяти |

Пока меню кошелька открыто, устройство принимает файлы и запросы с ПК. Файл
или запрос открывает свой экран подтверждения, после — снова меню.

### View-only кошелёк в Feather

1. В `mwlink_gui.py` нажмите **«Request view-only wallet data»**.
2. Устройство покажет запрос; подтвердите «Да» (откажите «Нет», если запрос не ваш).
3. В папке обмена появится `<кошелёк>_<время>_viewonly.json` (адрес, private
   view key, restore height), программа выведет их в журнал.
4. Feather: создание кошелька → восстановление из ключей (spend key оставить
   пустым — получится view-only кошелёк). Названия пунктов зависят от
   версии Feather.

«Request address» отдаёт только адрес — после простого «Да».

## 7. Синхронизация key images

Feather с view-only кошельком видит поступления, но **не знает, какие из
них потрачены** — для этого нужен секретный ключ. Устройство считает key
images и отдаёт их Feather.

1. Устройство: откройте кошелёк.
2. ПК: запустите `mwlink_gui.py`, **Connect**, в поле «Folder» — папка
   обмена, флажок **«Watch the folder»** включён.
3. Feather: в офлайн-подписи выберите экспорт выходов (sync key images →
   export outputs; названия пунктов зависят от версии) и сохраните файл в
   папку обмена (например `borya-view2_1789637203_outputs`). Если есть выбор,
   экспортируйте **все** выходы.
4. Программа отправит файл на устройство (его можно отправить и кнопкой
   **«Send file...»** — подойдёт любой файл, имя и расширение не важны).
5. Устройство: «Сгенерировать key images для N выходов?» → **Да**. Идёт
   расчёт с прогрессом.
6. В папке появится `borya-view2_<время>_keyImages`.
7. Feather: импорт key images → этот файл. Баланс обновится.

Устройство запоминает выданные key images (зашифрованный кэш на устройстве):
по нему оно потом проверяет транзакции.

## 8. Подпись транзакции

1. Feather: создайте перевод; view-only кошелёк предложит сохранить
   **неподписанную транзакцию** — сохраните в папку обмена
   (`1789839233_unsigned_monero_tx`).
2. Программа отправит файл на устройство.
3. Устройство проверяет файл:
   - сделан этим кошельком (подпись ключом просмотра) — иначе «файл от
     другого кошелька или варианта passphrase»;
   - каждый вход принадлежит кошельку и его key image выдан устройством —
     иначе «key image not synchronised»: сначала сделайте раздел 7 с
     экспортом **всех** выходов;
   - **адрес сдачи — адрес этого кошелька** (проверка на подмену); иначе
     отказ;
   - суммы сходятся.
4. **Экран транзакции**: сумма к отправке, комиссия, сдача, входы/выходы и
   каждый получатель — нажмите на строку, чтобы увидеть **адрес целиком**.
   Сверяйте полный адрес с тем, откуда вы его взяли: заражённый компьютер
   может подменить адрес в своём окне, экран устройства показывает то, что
   будет подписано.
5. **Подписать** → устройство считает Bulletproofs+ и CLSAG (прогресс на
   экране, не отключайте питание).
6. В папке появится `<время>_signed_monero_tx`. Feather: загрузите подписанную
   транзакцию, проверьте и отправьте в сеть.

Если перевод разбит Feather на несколько транзакций (до 4), устройство
покажет каждую отдельно. Если входы уже тратились транзакцией, подписанной
этим устройством раньше, будет предупреждение: если та ушла в сеть, новая
будет отклонена.

## 8a. Обмен через SD-карту (ES3C28P, Touch-LCD-2)

Вместо USB можно переносить файлы на карте microSD (FAT32).

1. Скопируйте файл из Feather (`…_outputs` или `…_unsigned_monero_tx`) в
   **корень** карты и вставьте карту в устройство.
2. Откройте кошелёк → **SD card files**. В списке только файлы, которые
   устройство умеет обработать, новые сверху: по дате, которую поставил
   компьютер, а если её нет — по времени в имени файла. Под именем — тип,
   размер и дата; уже обработанные помечены *done*. Длинное имя обрезается
   многоточием и прокручивается, когда строка выделена.
3. Выберите файл и подтвердите на устройстве — так же, как при обмене по USB
   (разделы 7 и 8).
4. Результат (`…_keyImages` или `…_signed_monero_tx`) появится рядом с
   исходным файлом, с той же датой. Загрузите его в Feather. Сообщение об
   успехе закрывается само через 2,5 с (или касанием); устройство сразу
   готово к следующему файлу — и по USB тоже.

Пока список открыт, устройство следит за картой: если её вынуть, список
очищается и просит вставить карту; как только карту вставят, список файлов
появляется сам. Открыть список можно и без карты.

**View key на SD-карту.** Пункт меню кошелька **View key to SD card**
записывает в корень карты файл `<имя кошелька>_viewonly.txt`: имя кошелька,
сеть, основной адрес, private view key и высоту восстановления — всё, что
нужно для view-only кошелька в Feather (*Restore wallet from keys → View
Only*). Перед записью устройство предупреждает: кто прочтёт файл, увидит все
входящие платежи (потратить он не сможет). Удалите файл после
использования. Символы, недопустимые в именах файлов FAT32/Windows
(`/ \ : * ? " < > |`), заменяются на `_`; если файл с таким именем уже есть,
к имени добавляется `_2`, `_3`…

При первом использовании устройство записывает на карту
`ColdPunk_readme.txt` с этой инструкцией. Размер файла — до 256 КБ.

Сразу после каждой записи устройство сбрасывает все буферы на карту и
отключает её, а при каждом открытии списка подключает заново. Поэтому карту
можно вынуть и вставить (ту же или другую) в любой момент, кроме самой
записи результата.

## 9. Журнал устройства

Окно «Device log» программы показывает, что делает устройство: открытие
кошелька, приём файла, ожидание подтверждения, результат, отказы с
причиной. **Настройки → Отладочный лог → Вкл** добавляет подробности
(индексы выходов, подадреса, число входов и выходов, размеры). Ключи,
seed, passphrase и key images в журнал не попадают никогда. Кнопка «Save
log...» сохраняет журнал в файл — его удобно приложить к сообщению об
ошибке.

---

## 10. Автоблокировка

После заданного в настройках времени без касаний (по умолчанию 5 минут)
устройство закрывает открытый экран, стирает ключи и пароль из памяти и
возвращается к игре. «0» в настройке отключает автоблокировку.

## 11. Проблемы

| Сообщение / симптом | Причина | Что делать |
| :--- | :--- | :--- |
| Кнопки программы: «no wallet is open on the device» | кошелёк не открыт | разблокировать устройство и открыть кошелёк |
| «not a Monero outputs export or unsigned transaction file» | отправлен не тот файл | отправить файл Feather (outputs / unsigned tx) |
| «this is a key image export / signed transaction» | файл, который делает устройство | загрузить его в Feather |
| «was made by a different wallet … passphrase variant?» | файл другого кошелька или открыт не тот вариант passphrase | открыть нужный кошелёк / вариант |
| «key image not synchronised» | Feather не знает о тратах | раздел 7, экспорт всех выходов, затем создать транзакцию заново |
| «possible change address substitution» | сдача уходит не на адрес кошелька | не подписывать; проверить компьютер |
| «Неверная passphrase» | опечатка | ввести ещё раз; пусто — кошелёк без passphrase |
| Адрес не совпадает с Feather | другой вариант passphrase или другая сеть | проверить passphrase и сеть в настройках |
| Подпись идёт долго | Bulletproofs+ на микроконтроллере | не отключать питание |
| Забыт passphrase | не восстанавливается | средства этого варианта недоступны |

### Чего делать нельзя

- вводить seed-фразу на компьютере или телефоне;
- фотографировать экран с seed-фразой или view key;
- хранить passphrase рядом с seed-фразой;
- подтверждать транзакцию, не прочитав адрес на **экране устройства**
  целиком.
