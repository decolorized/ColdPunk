# Руководство пользователя

Документ написан для человека, который пользуется устройством вместе с
кошельком Feather, а не пишет для него код.

---

## Прежде чем начать

**Устройство не прошло аудит безопасности и не проверено на реальных
средствах.** Пока не пройдена проверка в тестовой сети (stagenet), считайте
устройство демонстрационным и не храните на нём деньги, которые жалко
потерять.

Что нужно иметь:

- само устройство (ESP32-S3 с экраном) и USB-кабель с данными;
- компьютер с **Feather Wallet** и программой `mwlink_gui.py`
  (`tools/mwlink`, нужен Python 3 и `pip install pyserial hidapi`);
- бумагу и ручку — seed-фразу записывают на бумаге, не в телефоне.

---

## 1. Как устроена работа

Устройство никогда не подключается к интернету. Оно хранит ключи и делает
три вещи, каждую — только после подтверждения на своём экране:

1. по файлу выходов Feather считает **key images** (синхронизация баланса);
2. по неподписанной транзакции Feather делает **подписанную**;
3. по запросу ПК отдаёт **адрес** или данные для **view-only кошелька**
   (адрес и private view key).

```
   Feather (view-only)          mwlink_gui           Устройство
         |                          |                     |
   export outputs  --> папка --->   |  --- файл --->      |  вы подтверждаете,
         |                          |                     |  устройство считает
   import key images <- папка <---  |  <-- keyImages ---  |
         |                          |                     |
   create tx       --> папка --->   |  --- файл --->      |  вы сверяете сумму,
         |                          |                     |  адрес, комиссию
   submit          <-- папка <---   |  <-- signed tx ---  |  и подписываете
```

Программа на ПК только переносит файлы и показывает журнал устройства.
Seed-фраза, passphrase и private spend key никогда не покидают устройство.

Каналы обмена — USB HID, USB Serial (COM-порт) и SD-карта — выбираются при
сборке прошивки. Обычно включены все; если устройство собрано, например,
«только HID», программа на ПК должна подключаться по HID (MoneroPunkSigner и
`mwlink` так и делают по умолчанию). Подробнее — `build_arduino.md` §2a.

## 2. Включение: пароль (и игра, если включена)

По умолчанию устройство при включении и после каждой блокировки сразу
показывает **экран пароля**.

**Маскировка под «Сапёр» (по желанию).** **Настройки → Minesweeper at start
→ On**: устройство будет включаться (и возвращаться после блокировки) как
обычная игра **«Сапёр»**, в которой ничего не говорит о кошельке: касание
открывает клетку, долгое касание или режим **F** ставит флажок, **↻**
начинает новую игру. Перед включением устройство показывает инструкцию и
включает игру, только если нажать **Turn on**.

**Как из игры попасть к паролю:** подорвитесь на мине, затем **трижды быстро
(за 2 секунды) коснитесь взорванной мины** (клетка с крестиком). На платах с
кнопками: выберите взорванную мину и трижды нажмите SELECT. Другие касания
сбрасывают счёт. Другого выхода из игры нет — запомните жест. Это маскировка,
а не защита: защищает пароль. Выключить игру — тот же пункт настроек, Off.

Если устройство обновлено с прошивки старше 0.3.4 (там игра была всегда),
игра остаётся включённой, пока её не выключат в настройках.

**Первое включение: ключ в чипе.** Если в чипе ещё нет секретного ключа
(eFuse), устройство сначала предложит записать его — до пароля. Без этого
ключа устройство не работает: «Отмена» возвращает к началу. Ключ случайный,
записывается один раз и навсегда в старший свободный блок ключей eFuse
(обычно `BLOCK_KEY5`; номер блока показан на экране) и не читается даже
прошивкой — только используется. Запись **необратима**: два подтверждения и
ввод кода. Состояние блоков — **Настройки → eFuse key blocks**.

Дальше устройство спросит **пароль аккаунта**:

- при **первом включении** его нужно придумать (от 8 до 64 символов) и
  ввести дважды — без пароля пользоваться устройством нельзя. На пароль только
  из цифр, из одного повторяющегося символа или вида `abcdefgh` устройство
  предупредит: такой пароль подберут, если устройство украдут. Пароли из 4–7
  символов, заданные прежними прошивками, по-прежнему открывают устройство,
  но любой новый пароль должен быть не короче 8 символов;
- потом — вводить при каждом входе.

**Неверный пароль.** Счётчик ошибок один на всё устройство:

- первые 10 ошибок — без задержки; дальше каждая следующая попытка
  откладывается: 1 минута, 2, 4 … до 8 часов. Если с момента включения уже
  был вход в любой аккаунт, задержка не больше 10 минут. Устройство не знает
  времени: задержка идёт, пока оно включено, после перезагрузки начинается
  заново;
- с 45-й ошибки перед каждым вводом пароля нужно набрать число с экрана
  (защита от детей) и видно, сколько попыток осталось;
- на **50-й ошибке устройство стирает всё** (как сброс к заводским);
- счётчик обнуляется любым верным паролем (вход в любой аккаунт).

Пароль вместе с ключом внутри чипа шифрует все seed-фразы. «Отмена» на
экране пароля (и тайм-аут ввода) возвращает к игре, если она включена, иначе
снова к экрану пароля.

**Сброс без пароля.** Введите в поле пароля фразу
`Reset My Device 1029384756` и подтвердите кодом: устройство сотрёт все
аккаунты и кошельки. Это выход, если ни один пароль больше ничего не
открывает. Фраза работает и во время задержки; паролем её задать нельзя.
(В своей сборке фразу можно поменять: `MW_RESET_PHRASE` в `app_config.h`.)

## 2a. Аккаунты

Аккаунты нужны, чтобы при принуждении показать не все активы. У каждого
аккаунта свой пароль, своё имя и свои кошельки:

- пароль аккаунта 1 открывает кошельки аккаунта 1, пароль аккаунта 2 —
  кошельки аккаунта 2;
- аккаунт не видит другие аккаунты и их кошельки; на устройстве нигде нет
  списка аккаунтов и их числа;
- удалить аккаунт можно только его же паролем.

Имя аккаунта видно под заголовком главного меню и в **Настройки → Account
name**, там же его можно сменить (от 1 до 15 символов). Его видит только сам
аккаунт. Первый аккаунт называется «Main».

**Добавить:** Настройки → **Add account**: имя нового аккаунта, затем его
пароль дважды. Пароль, который уже есть у какого-то аккаунта, не подойдёт
(«This password cannot be used»), и такая попытка считается как неверный
пароль — иначе так можно было бы подбирать чужие пароли. После добавления вы
остаётесь в своём аккаунте; чтобы войти в новый, заблокируйте устройство и
введите его пароль.

**Удалить свой аккаунт:** Настройки → **Delete this account**:
предупреждение, ввод кода и свой пароль. Удаляются все кошельки этого
аккаунта и его кэши key images, затем устройство блокируется. Другие аккаунты
не затрагиваются. Если других нет, устройство **не** сбрасывается само
(иначе по этому было бы видно, что других аккаунтов нет): войти будет
некуда, выход — фраза сброса на экране пароля.

**Сменить пароль:** Настройки → пароль — меняется пароль того аккаунта, в
который вы вошли.

**Пароль** — всегда от 8 до 64 символов: при первой настройке, при смене и
при добавлении аккаунта. (Более короткий пароль, заданный старыми
прошивками, по-прежнему открывает устройство.)

Общее для всех: настройки (сеть новых кошельков, клавиатура, яркость,
автоблокировка, калибровка), ключ eFuse и счётчик неверных попыток — ошибки
при вводе любого пароля задерживают следующие попытки для всех. **Сброс к
заводским** стирает все аккаунты и все кошельки. Свои у каждого аккаунта:
имя, кошельки и **Учёт баланса** (вкл/выкл).

Аккаунтов — от 16 до 24: точное число своё у каждого чипа и нигде не
показывается, чтобы, заполняя аккаунты до отказа, нельзя было узнать, сколько
их было. У каждого до 64 кошельков.

Счётчик ошибок рассчитан на того, кто не знает ни одного пароля: кто знает
пароль одного аккаунта, обнуляет счётчик входом. Подробно — `security.md` §4a.

Что видно, если снять дамп флеш-памяти: на устройстве всегда ровно 24
слота — каталог и файл кэша key images на каждый, один слот на аккаунт,
остальные пустышки того же размера, — поэтому число аккаунтов по ним не
определить. Файл кэша занимает 64 КБ и растёт по 64 КБ, только если у
аккаунта очень много выходов (больше ~790); такой большой файл выдаёт, что
это аккаунт. Поэтому **каждый раз, когда файл перерастает очередные 64 КБ,
устройство предупреждает**: безопасность снижена, лучше создать новый
кошелёк и перевести средства на него. Число key images не ограничено — лишь
бы хватило памяти устройства; если память кончится, устройство скажет об
этом, а результат операции останется верным.

**Обновление до 0.3.** При первом включении устройство один раз
переводит хранилище с FAT на LittleFS («Storage update»): лишние слоты
удаляются, файлы читаются в память (PSRAM) и проверяются, затем экран
показывает число файлов и просит код. **Около минуты после кода нельзя
выключать питание**: раздел стирается и файлы пишутся обратно, и обрыв в
это время сотрёт кошельки (устройство сообщит об этом при следующем
включении — восстановите их из seed). Отказ оставляет старый формат, перевод
предложат при следующем включении. Перед обновлением проверьте, что
seed-фразы записаны на бумаге.

**Обновление с прошлой сборки.** При первом входе после обновления формат
переводится автоматически: каталог аккаунта и его кэши key images переходят
в новый вид, старые пустышки заменяются, а каталоги аккаунтов, в которые
ещё не входили, дополняются до нового размера. Кэши такого аккаунта
переносятся при его первом входе.

---

**Прошивка только с кнопкой BOOT** (0.3.6, Настройки → **Flash only with
BOOT**). Прошивка сама уже не переводит чип в режим загрузки: на USB-порту
до входа нет даже «USB JTAG/serial debug unit», а запросы «перезагрузись в
загрузчик» игнорируются. Пункт настроек прожигает eFuse: JTAG выключается, а
программно войти в режим загрузки больше нельзя — только с зажатой BOOT при
сбросе или подключении. Обновлять прошивку можно и дальше, с кнопкой.
Необратимо: предупреждения, число с экрана, пароль аккаунта. Если на плате
USB-UART мост (CH340/CP210x) сам дёргает BOOT и RESET — `flash.bat`
прошивал без кнопки, — для чипа это та же кнопка, и eFuse его не остановят:
не подключайте этот порт к ПК или уберите транзисторы автосброса. Чужую
прошивку останавливает только secure boot.

**Запрет перепрошивки** (Настройки → **Lock firmware updates**). Прожигает
eFuse, которые навсегда отключают JTAG и режим загрузки по USB/UART:
прошивку больше нельзя ни прочитать, ни заменить по кабелю — и **обновить
тоже нельзя никогда**. Необратимо: три предупреждения, число с экрана и
пароль аккаунта. От программатора, подключённого прямо к микросхеме
флеш-памяти, это не защищает (это делает только secure boot).

## 4. Создание кошелька

Кошельки → **Создать кошелёк**.

1. **Имя** кошелька.
2. **Формат seed-фразы**: Monero legacy (25 слов) или Polyseed (16 слов,
   хранит дату создания — restore height не нужен).
3. **Источник случайности**: аппаратный ГСЧ или 100 бросков кубика.
4. **Запишите слова на бумагу** — по порядку, с номерами. Устройство не
   покажет их второй раз.
5. **Проверка**: устройство попросит несколько слов по номерам.
6. **Passphrase** (см. ниже) — ввести дважды или явно выбрать «Без
   passphrase» с двумя подтверждениями.
7. Устройство покажет **адрес** — сверьте его потом с Feather.

### Passphrase: два кошелька на одну фразу

Passphrase — дополнительное слово к seed-фразе. Если вы его задали, у
записи на устройстве **два кошелька**:

**Как открывается (0.3.5).** Выбор кошелька в списке всегда открывает его
**без passphrase**, сразу и без вопросов. Чтобы открыть кошелёк с passphrase,
в меню кошелька выберите **«Открыть с passphrase»** и введите её:

| Введено в «Открыть с passphrase» | Результат |
| :--- | :--- |
| ваш passphrase | открывается кошелёк с passphrase (в заголовке «С passphrase») |
| что-то другое | «Неверная passphrase» |
| любой текст у кошелька без passphrase | «Неверная passphrase» |

Пункт есть у **каждого** кошелька, экран, время проверки (около секунды и
больше) и ответ одинаковые — по устройству нельзя понять, у какого кошелька
есть passphrase. Отметка «С passphrase» видна только после такого входа;
в списке кошельков никаких отметок нет.

Устройство не хранит сам passphrase. У каждого кошелька в зашифрованном
каталоге есть запись одного размера: ключ кошелька с passphrase,
зашифрованный ключом из passphrase (500 000 раундов PBKDF2 вместе с
ключом eFuse этого чипа), — или случайные байты. Долгий расчёт CryptoNight
делается один раз, при создании или импорте.

**Passphrase задаётся только при создании или импорте.** Добавить, сменить
или убрать её у существующего кошелька нельзя — для этого кошелёк удаляют и
импортируют заново той же фразой.

Кошельки с passphrase, созданные прошивкой до 0.3.5, при первом «Открыть с
passphrase» открываются по-старому (несколько секунд, CryptoNight) и после
этого получают новую запись.

В Feather такой кошелёк восстанавливается той же фразой, если в мастере
восстановления указать passphrase в поле seed offset (смещение seed).
Устройство использует ту же схему, что Feather и Monero CLI
(`cryptonote::decrypt_key`), для 25 и для 16 слов.

**Забытый passphrase не восстанавливается.** Запишите его отдельно от
seed-фразы.


**Подсказка passphrase.** После ввода passphrase при создании или импорте
устройство предложит подсказку — до 31 символа, можно оставить пустой. Её
покажут в «Открыть с passphrase» перед вводом. Пункт **Passphrase hint**
есть в меню каждого кошелька: посмотреть, изменить или очистить (пустая
строка); подсказку можно задать и кошельку без passphrase. Подсказку видит
каждый, кто вошёл в этот аккаунт: не пишите в неё сам passphrase.

## 5. Импорт кошелька

Кошельки → **Импортировать кошелёк** → 25 слов, 16 слов или ключи.

1. Имя, затем слова: первые буквы → выбор из списка. Если контрольная сумма
   не сошлась, устройство подсветит слово, с которого проверять.
2. Passphrase — как при создании: пусто, если его не было.
3. Для 25 слов — restore height (номер блока; 0, если не знаете).
4. Сверьте адрес с Feather.

Импорт по ключам (spend + view или view-only) создаёт кошелёк без варианта
с passphrase.

**16 слов из Cake Wallet / Cupcake.** Там passphrase шифрует саму фразу
(флаг «encrypted» в polyseed), а не применяется как seed offset. Устройство
определяет формат по фразе само: для такой фразы оно сообщает «Фраза
зашифрована passphrase (Cake Wallet / Cupcake)», и passphrase при импорте
обязательна. Без неё (обычное открытие) такой кошелёк открывается как
другой, пустой кошелёк — настоящий открывается через «Открыть с
passphrase». В Feather такую фразу восстановить нельзя («Encrypted seeds are
not supported»): кошелёк для просмотра в Feather создаётся из ключа
просмотра (View key / `_viewonly.txt`). Ошибку в passphrase polyseed
обнаружить не может: получится другой кошелёк, поэтому сверьте адрес с
Cupcake. Новые кошельки устройство всегда создаёт в формате Feather
(фраза не зашифрована, passphrase — seed offset). MoneroPunkSigner тоже
восстанавливает такие фразы: при вводе 16 слов он спросит их passphrase.

## 6. Меню кошелька

Кошельки → выберите кошелёк. Заголовок — имя кошелька, под ним «С
passphrase» (только в кошельке, открытом с passphrase) и состояние связи:
**«Готов к приёму файлов с ПК»**.

| Пункт | Что делает |
| :--- | :--- |
| Адрес | адрес текстом |
| Balance | примерный остаток и список транзакций (если учёт баланса включён) |
| Открыть с passphrase | ввести passphrase и открыть кошелёк с ней (есть у каждого кошелька) |
| Private view key | ключ текстом, после предупреждения |
| Переименовать | новое имя |
| Network | сеть **этого** кошелька: Mainnet / Testnet / Stagenet |
| Check seed | ввести seed-фразу и узнать, совпадает ли она с кошельком (для кошельков из seed) |
| Удалить кошелёк | после ввода показанного числа; стираются запись и кэш key images |
| Закрыть кошелёк | ключи стираются из памяти |

**Сеть.** С версии 0.3 сеть хранится у каждого кошелька. Новый кошелёк
получает сеть из **Настройки → New wallets' network**; кошельки, созданные
раньше, берут её оттуда же, пока им не задать свою в меню кошелька.

**Check seed.** Устройство попросит слова фразы (25 или 16, по типу
кошелька) и ответит только «совпадает» или «не совпадает» — без подсказки,
какое слово неверно. Passphrase в проверке не участвует. Кошельку из ключей
пункт не показывается.

**Balance.** Устройство считает остаток по выгрузкам выходов из Feather
(сумма каждого выхода и отметка «потрачен») и по транзакциям, которые само
подписало (входы — потрачены, сдача — добавлена). Это оценка «на момент
последней синхронизации»: если подписанную транзакцию не отправили в сеть,
следующая выгрузка выходов вернёт её входы. Остаток можно ввести вручную
(**Enter by hand**) — он держится до следующей синхронизации; **Use the
estimate** возвращает расчётный. **Транзакции** — всё, что устройство знает
(прокручивается пальцем и кнопками вверх/вниз, влево/вправо — страница):

- **Получено** — выходы из выгрузок outputs, сгруппированные по транзакциям,
  новые сверху (по глобальному индексу выхода); у каждой — сумма, число
  выходов и отметка «потрачено»;
- `*` — подписано на этом устройстве: список подписанных транзакций (номер,
  сумма, начало адреса, комиссия; дат нет — у устройства нет часов), до 200
  последних на кошелёк, а среди полученных — сдача таких транзакций;
- `?` — устройство знает не всё: выходы, потраченные не этим устройством
  (известна только их сумма, не транзакция), выходы без известной
  транзакции (синхронизированы прошивкой до 0.3.5) и выходы с неизвестной
  суммой.

Всё хранится зашифрованным в файле аккаунта.

**«Сумма неизвестна».** Такие выходы остались от прошивок до 0.3 или пришли
вместе с неподписанной транзакцией (кошелёк на ПК просит key images новых
выходов прямо в ней; прошивка до 0.3.5 не запоминала их суммы, а в
следующую обычную выгрузку они уже не попадают — она начинается после
последнего известного key image). Выгрузите в кошельке на ПК **все** outputs
(monero-wallet-cli: `export_outputs all FILE`) и передайте устройству:
выгрузка с первого выхода — полный список кошелька; выходы с неизвестной
суммой, которых в ней нет, больше не считаются. Если после частичной
выгрузки такие выходы остаются, устройство само это подскажет.

**Настройки → Balance tracking: Off** выключает учёт для аккаунта и
стирает накопленные суммы и списки.

Пока меню кошелька открыто, устройство принимает файлы и запросы с ПК. Файл
или запрос открывает свой экран подтверждения, после — снова меню.

### View-only кошелёк в Feather

1. В `mwlink_gui.py` нажмите **«Request view-only wallet data»**.
2. Устройство покажет запрос; подтвердите «Да» (откажите «Нет», если запрос не ваш).
3. В папке обмена появится `<кошелёк>_<время>_viewonly.json` (адрес, private
   view key, restore height), программа выведет их в журнал.
4. Feather: создание кошелька → восстановление из ключей (spend key оставить
   пустым — получится view-only кошелёк). Названия пунктов зависят от
   версии Feather.

«Request address» отдаёт только адрес — после простого «Да».

## 7. Синхронизация key images

Feather с view-only кошельком видит поступления, но **не знает, какие из
них потрачены** — для этого нужен секретный ключ. Устройство считает key
images и отдаёт их Feather.

1. Устройство: откройте кошелёк.
2. ПК: запустите `mwlink_gui.py`, **Connect**, в поле «Folder» — папка
   обмена, флажок **«Watch the folder»** включён.
3. Feather: в офлайн-подписи выберите экспорт выходов (sync key images →
   export outputs; названия пунктов зависят от версии) и сохраните файл в
   папку обмена (например `borya-view2_1789637203_outputs`). Если есть выбор,
   экспортируйте **все** выходы.
4. Программа отправит файл на устройство (его можно отправить и кнопкой
   **«Send file...»** — подойдёт любой файл, имя и расширение не важны).
5. Устройство: «Сгенерировать key images для N выходов?» → **Да**. Идёт
   расчёт с прогрессом. Галочка **«Все сохранённые key images»** под
   вопросом (показывается всегда) добавляет в ответ key images более ранних
   выходов, которые устройство уже выдавало (см. ниже).
6. В папке появится `borya-view2_<время>_keyImages`.
7. Feather: импорт key images → этот файл. Баланс обновится.

Устройство запоминает выданные key images (зашифрованный кэш на устройстве):
по нему оно потом проверяет транзакции.

**Все сохранённые key images.** Кошелёк на ПК обычно выгружает только новые
выходы (файл начинается не с первого перевода). С галочкой устройство
ставит перед ними key images более ранних выходов, которые оно уже выдавало
раньше вместе с их номером в кошельке на ПК: непрерывный ряд номеров, что
кончается прямо перед первым выходом файла. Это помогает, когда кошелёк на
ПК потерял key images (восстановлен заново, пересканирован без
`keep_ki`), а сделать полный экспорт выходов неудобно. Чего у устройства
нет, оно не придумывает: после выгрузки оно пишет, сколько добавлено и с
какого выхода, или что раньше этого файла ничего нет (например первый номер
не был выдан ни разу, или кошелёк на ПК пронумеровал выходы иначе). Всё
недостающее даёт только экспорт **всех** выходов. Номера запоминаются с
версии 0.3.5 (после обновления их узнаёт первая же выгрузка). Кошелёк на
ПК проверяет каждую подпись по своему списку переводов: при чужой нумерации
он отклонит файл целиком, ничего не испортив — тогда выгрузите без
галочки.

**Баланс 0 и нет исходящих транзакций в Feather.** После импорта key images
кошелёк на ПК знает, какие выходы потрачены (баланс уменьшается), но
исходящие транзакции показывает, только когда заново просканирует блоки,
уже зная key images. Пересканируйте блокчейн с сохранением key images:
в monero-wallet-cli `rescan_bc keep_ki`, в Feather и GUI — пересканирование
с высоты восстановления. Это поведение самого кошелька Monero, а не
устройства; так же ведёт себя второй кошелёк на ПК с тем же view key.

## 8. Подпись транзакции

1. Feather: создайте перевод; view-only кошелёк предложит сохранить
   **неподписанную транзакцию** — сохраните в папку обмена
   (`1789839233_unsigned_monero_tx`).
2. Программа отправит файл на устройство.
3. Устройство проверяет файл:
   - сделан этим кошельком (подпись ключом просмотра) — иначе «файл от
     другого кошелька или варианта passphrase»;
   - каждый вход принадлежит кошельку и его key image выдан устройством —
     иначе «key image not synchronised»: сначала сделайте раздел 7 с
     экспортом **всех** выходов;
   - **адрес сдачи — адрес этого кошелька** (проверка на подмену); иначе
     отказ;
   - суммы сходятся.
4. **Экран транзакции**: сумма к отправке, комиссия, сдача, входы/выходы и
   каждый получатель — нажмите на строку, чтобы увидеть **адрес целиком**.
   Сверяйте полный адрес с тем, откуда вы его взяли: заражённый компьютер
   может подменить адрес в своём окне, экран устройства показывает то, что
   будет подписано.
5. **Подписать** → устройство считает Bulletproofs+ и CLSAG (прогресс на
   экране, не отключайте питание).
6. В папке появится `<время>_signed_monero_tx`. Feather: загрузите подписанную
   транзакцию, проверьте и отправьте в сеть.

Если перевод разбит Feather на несколько транзакций (до 4), устройство
покажет каждую отдельно. Если входы уже тратились транзакцией, подписанной
этим устройством раньше, будет предупреждение: если та ушла в сеть, новая
будет отклонена.

## 8a. Обмен через SD-карту (ES3C28P, Touch-LCD-2)

Вместо USB можно переносить файлы на карте microSD (FAT32).

1. Скопируйте файл из Feather (`…_outputs` или `…_unsigned_monero_tx`) в
   **корень** карты и вставьте карту в устройство.
2. Откройте кошелёк → **SD card files**. В списке только файлы, которые
   устройство умеет обработать, новые сверху: по дате, которую поставил
   компьютер, а если её нет — по времени в имени файла. Под именем — тип,
   размер и дата; уже обработанные помечены *done*. Длинное имя обрезается
   многоточием и прокручивается, когда строка выделена.
3. Выберите файл и подтвердите на устройстве — так же, как при обмене по USB
   (разделы 7 и 8).
4. Результат (`…_keyImages` или `…_signed_monero_tx`) появится рядом с
   исходным файлом, с той же датой. Загрузите его в Feather. Сообщение об
   успехе закрывается само через 2,5 с (или касанием); устройство сразу
   готово к следующему файлу — и по USB тоже.

Пока список открыт, устройство следит за картой: если её вынуть, список
очищается и просит вставить карту; как только карту вставят, список файлов
появляется сам. Открыть список можно и без карты.

**View key на SD-карту.** Пункт меню кошелька **View key to SD card**
записывает в корень карты файл `<имя кошелька>_viewonly.txt`: имя кошелька,
сеть, основной адрес, private view key и высоту восстановления — всё, что
нужно для view-only кошелька в Feather (*Restore wallet from keys → View
Only*). Перед записью устройство предупреждает: кто прочтёт файл, увидит все
входящие платежи (потратить он не сможет). Удалите файл после
использования. Символы, недопустимые в именах файлов FAT32/Windows
(`/ \ : * ? " < > |`), заменяются на `_`; если файл с таким именем уже есть,
к имени добавляется `_2`, `_3`…

При первом использовании устройство записывает на карту
`ColdPunk_readme.txt` с этой инструкцией. Размер файла — до 256 КБ.

Сразу после каждой записи устройство сбрасывает все буферы на карту и
отключает её, а при каждом открытии списка подключает заново. Поэтому карту
можно вынуть и вставить (ту же или другую) в любой момент, кроме самой
записи результата.

## 9. Журнал устройства

Окно «Device log» программы показывает, что делает устройство: открытие
кошелька, приём файла, ожидание подтверждения, результат, отказы с
причиной. **Настройки → Отладочный лог → Вкл** добавляет подробности
(индексы выходов, подадреса, число входов и выходов, размеры). Ключи,
seed, passphrase и key images в журнал не попадают никогда. Кнопка «Save
log...» сохраняет журнал в файл — его удобно приложить к сообщению об
ошибке.

---

## 10. Автоблокировка

После заданного в настройках времени без касаний (по умолчанию 5 минут)
устройство закрывает открытый экран, стирает ключи и пароль из памяти и
возвращается к игре. «0» в настройке отключает автоблокировку.

## 11. Проблемы

| Сообщение / симптом | Причина | Что делать |
| :--- | :--- | :--- |
| Кнопки программы: «no wallet is open on the device» | кошелёк не открыт | разблокировать устройство и открыть кошелёк |
| «not a Monero outputs export or unsigned transaction file» | отправлен не тот файл | отправить файл Feather (outputs / unsigned tx) |
| «this is a key image export / signed transaction» | файл, который делает устройство | загрузить его в Feather |
| «was made by a different wallet … passphrase variant?» | файл другого кошелька или открыт не тот вариант passphrase | открыть нужный кошелёк / вариант |
| «key image not synchronised» | Feather не знает о тратах | раздел 7, экспорт всех выходов, затем создать транзакцию заново |
| «possible change address substitution» | сдача уходит не на адрес кошелька | не подписывать; проверить компьютер |
| «Неверная passphrase» | опечатка | ввести ещё раз; пусто — кошелёк без passphrase |
| Адрес не совпадает с Feather | другой вариант passphrase или другая сеть | проверить passphrase и **Network** в меню кошелька |
| «The key image cache of this account has grown» | файл кэша аккаунта перерос очередные 64 КБ | создать новый кошелёк и перевести средства на него |
| «Too many attempts. Wait …» | много неверных паролей | дождаться (устройство должно быть включено) или ввести верный пароль позже; фраза сброса работает и сейчас |
| Подпись идёт долго | Bulletproofs+ на микроконтроллере | не отключать питание |
| Программа не находит устройство по HID | прошивка собрана без HID (`MW_USE_HID 0`) или с USB Mode = Hardware CDC | подключиться по COM-порту (`mwlink --serial`) или пересобрать, `build_arduino.md` §2a |
| COM-порт есть, но устройство молчит | прошивка собрана без Serial (`MW_USE_SERIAL 0`) | подключиться по HID |
| Нет пункта «SD card files» | у платы нет слота или прошивка собрана с `MW_USE_SD 0` | обмен по USB |
| Забыт passphrase | не восстанавливается | средства этого варианта недоступны |

### Чего делать нельзя

- вводить seed-фразу на компьютере или телефоне;
- фотографировать экран с seed-фразой или view key;
- хранить passphrase рядом с seed-фразой;
- подтверждать транзакцию, не прочитав адрес на **экране устройства**
  целиком.
