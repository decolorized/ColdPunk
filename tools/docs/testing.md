# Тестирование

ТЗ раздел 13. Документ описывает, как запускать хостовые тесты, что они
покрывают, что на хосте проверить невозможно, и процедуру проверки в
stagenet (ТЗ 13.6).

---

## 1. Хостовый набор тестов

### Запуск

```
cd tools/test
make run
```

Или просто `make` — цель по умолчанию `all` зависит от `run`.

Что происходит:

1. компилируется платформонезависимое ядро — `src/crypto/*.c`,
   `src/monero/*.c`, `src/data/*.c`, `src/wallet/*.c`, `src/transfer/*.c`,
   `src/hal/hal_host.c` и `src/hal/log.c` (переменная `CORE_SRC` в
   `tools/test/Makefile`). Наборы task2: `test_link` (USB-линк), `test_device_auth`
   (пароль устройства), `test_log` (единый лог); `test_wallet_store` и
   `test_session` устанавливают пользовательский ключ, без которого
   запечатывание теперь отказывает;
2. компилируется каждый файл `test_*.c` в отдельный исполняемый файл в
   `tools/test/build/`;
3. все они запускаются по очереди;
4. если хоть один вернул ненулевой код — печатается `SUITES FAILED` и
   `make` завершается с ошибкой; иначе `ALL SUITES PASSED`.

ESP32 для этого не нужен: сборка идёт обычным `gcc` с
`-std=c11 -Wall -Wextra -O2 -g -DMW_HOST_BUILD=1`.

**Windows.** Подходит переносимый w64devkit (gcc + make + busybox, без
установки): распаковать, добавить `w64devkit/bin` в `PATH`, в его `sh`
выполнить `cd tools/test && make run`. Хостовый ГСЧ на Windows берёт энтропию из
`rand_s()` (RtlGenRandom); раньше он читал только `/dev/urandom`, из-за чего
на Windows «зависали» наборы с CLSAG и Bulletproofs+.

### Полезные цели

| Команда | Что делает |
| :--- | :--- |
| `make run` | собрать и прогнать всё |
| `make` | то же самое |
| `make V=1` | подробный вывод |
| `make asan` | пересобрать с AddressSanitizer и UBSan и прогнать (`-fsanitize=address,undefined -fno-omit-frame-pointer -O1`) |
| `make test_mnemonic` | собрать и прогнать один набор |
| `make clean` | удалить `build/` |
| `make ASAN=1 run` | то же, что `make asan` |
| `CC=clang make run` | собрать другим компилятором |

`make asan` стоит гонять отдельно от `make run`: объектные файлы собираются
с другими флагами, а `Makefile` не различает конфигурации по каталогам.
Если переключаетесь между обычной и ASan-сборкой, делайте `make clean`.

### Добавление набора тестов

Создать файл `tools/test/test_<имя>.c` — `Makefile` подхватит его автоматически
(`SUITES := $(basename $(notdir $(wildcard test_*.c)))`, исключая
`test_framework`). Скелет:

```c
#include "test_framework.h"
#include "monero/mnemonic.h"

MW_TEST(legacy_roundtrip) {
    uint8_t seed[32] = {0};
    uint16_t idx[MW_LEGACY_SEED_WORDS];
    const mw_wordlist_t* wl = mw_wordlist(MW_WL_MONERO_EN);
    CHECK_EQ_INT(mw_legacy_seed_encode(seed, wl, idx), MW_OK);
    uint8_t back[32];
    CHECK_EQ_INT(mw_legacy_seed_decode(idx, wl, back), MW_OK);
    CHECK_EQ_MEM(seed, back, 32);
}

int main(void) {
    RUN_TEST(legacy_roundtrip);
    return mw_test_summary();
}
```

Макросы фреймворка — `CHECK`, `CHECK_EQ_INT`, `CHECK_EQ_MEM` (с hex-дампом
обеих сторон), `CHECK_EQ_STR`; разбор hex-векторов — `mw_test_hex()`.
Всё объявлено в `tools/test/test_framework.h`.

### Детерминированные подписи

Подписи CLSAG и Bulletproofs+ используют случайные нонсы, поэтому обычно
невоспроизводимы. Для тестов в `src/crypto/random.h` предусмотрено:

```c
void mw_random_set_test_source(const uint8_t* stream, size_t len);
```

— «Host-test only: replace the entropy source with a deterministic stream so
signatures become reproducible. No-op on the device build». Это единственный
способ сверить подпись с эталонным вектором байт в байт.

## 2. Что покрывают наборы тестов

Сопоставление требований ТЗ 13.1–13.4 с модулями. Конкретных файлов
`test_*.c` в репозитории на момент написания документа нет — таблица
описывает, что должно быть покрыто и чем.

### ТЗ 13.1 — модульные тесты криптографии

| Требование ТЗ | Что проверять | Модуль |
| :--- | :--- | :--- |
| Скалярная арифметика | `mw_sc_add/sub/mul/muladd/mulsub/invert`, приведение mod `l`, `mw_sc_check` на границе `l` | `crypto/ed25519.h` |
| Операции на кривой | `mw_ge_scalarmult_base` против векторов, `mw_ge_add/sub/dbl`, round-trip компрессии | `crypto/ed25519.h` |
| Хеш-функции | Keccak-256 против векторов Monero `cn_fast_hash`, SHA-256/512 против NIST, HMAC против RFC 4231, PBKDF2 против RFC 6070 | `crypto/hash.h` |
| Bulletproofs+ | `mw_bpp_prove` → `mw_bpp_verify`, отказ на испорченном доказательстве, `mw_bpp_serialize`/`deserialize` round-trip | `monero/bulletproof_plus.h` |
| CLSAG | `mw_clsag_sign` → `mw_clsag_verify`, отказ при подмене сообщения, кольца, key image | `monero/clsag.h` |
| Сериализация | varint round-trip включая 10-байтовые значения, `mw_pba_*`, поведение `overflow` при чтении за границу | `monero/serialize.h` |
| `H_BYTES == ge_p3_H` | `MW_POINT_H` совпадает со сжатием `MW_GE_P3_H` | `crypto/ed25519.h` |
| `get_exponent` | `mw_bp_get_exponent` детерминирован и каждый результат в главной подгруппе | `crypto/ed25519.h` |
| Подгруппа для всех точек | `mw_point_in_main_subgroup` принимает валидные и отвергает точки малого порядка | `crypto/ed25519.h` |

Отдельно стоит проверить `mw_point_check_public` на восьми точках малого
порядка ed25519 — это классический источник уязвимостей.

### ТЗ 13.2 — тесты ввода seed

| Требование | Что проверять на хосте | Модуль |
| :--- | :--- | :--- |
| Корректность словарей | `count` = 1626 / 2048, уникальность префиксов (3 и 4 символа), сортировка для Polyseed | `data/wordlist.h` |
| Checksum Monero legacy | `mw_legacy_checksum_index`, отказ при порче слова | `monero/mnemonic.h` |
| Полиномиальный код Polyseed | `mw_polyseed_encode`/`decode` round-trip, отказ при порче, извлечение birthday | `monero/mnemonic.h` |
| Автодополнение по префиксу | `mw_wordlist_prefix_matches`, `mw_wordlist_next_letters` | `data/wordlist.h` |
| Ввод на всех разрешениях | **не тестируется на хосте** | UI |
| Кнопочный и сенсорный ввод | **не тестируется на хосте** | UI |
| Очистка буферов, таймаут | `mw_memzero`, `mw_ct_is_zero`; таймаут — только на устройстве | `crypto/memzero.h` |
| Сохранение типа клавиатуры в NVS | **не тестируется на хосте** | `wallet/secure_storage.h` |

### ТЗ 13.3 — passphrase

| Требование | Где проверяется |
| :--- | :--- |
| Обязательный запрос после seed | только на устройстве (`mw_flow_passphrase`) |
| Двойной ввод | только на устройстве |
| Пустой passphrase с явным подтверждением | только на устройстве |
| Обнуление буфера после использования | частично на хосте (`mw_memzero`, `mw_ct_is_zero`), полностью — на устройстве |

На хосте проверяемо главное свойство схемы: `mw_seed_to_keys` с пустым
passphrase и без passphrase дают **одинаковые** ключи, а с разными
непустыми passphrase — **разные**.

### ТЗ 13.4 — генерация seed

| Требование | Что проверять | Модуль |
| :--- | :--- | :--- |
| TRNG → корректная фраза | с `mw_random_set_test_source` — детерминированная фраза из известной энтропии | `crypto/random.h`, `monero/mnemonic.h` |
| Кубики → корректная фраза | PBKDF2-SHA512 2048 раундов над известной последовательностью бросков | `crypto/hash.h` |
| Соответствие адреса seed-фразе | seed → `mw_seed_to_keys` → `mw_address_from_keys` → сверка с эталонным адресом Monero | `monero/keys.h`, `monero/address.h` |
| Restore height для Polyseed | `mw_polyseed_birthday_time`, `mw_polyseed_restore_height` | `monero/mnemonic.h` |

Эталонные адреса надо брать из `monero-wallet-cli` для тех же seed-фраз —
это главный тест совместимости всего вывода ключей.

### ТЗ 13.5 — интеграционные тесты

| Требование | Хост | Устройство |
| :--- | :--- | :--- |
| выходы → key images | да: `test_feather_flow` на файлах независимого кодировщика | да, с настоящим Feather |
| неподписанный → подписанный набор | да: `test_feather_flow`, транзакция проверяется как узлом | да, с Feather и узлом |
| Feather Wallet (SD, QR) | нет | да |
| Monero GUI/CLI (SD) | нет | да |
| USB MSC: Unit Attention | нет | да |
| USB MTP: видимость без переподключения | нет | да |
| Floppy | нет | да |

Часть, которую можно вытащить на хост: сохранить реальные `outputs.bin` и
`unsigned_tx_set.bin`, снятые с Feather для тестового кошелька, положить их
в `test/data/` и прогонять `mw_file_open` → `mw_parse_*` → `mw_build_*` →
`mw_file_seal` в обычном тесте. Это ловит регрессии в парсерах без железа.

Важно: такие файлы содержат view key тестового кошелька (иначе их не
расшифровать). Используйте **только** кошелёк stagenet, созданный ради
тестов, и никогда не кладите в репозиторий файлы от кошелька с реальными
средствами.

### UR (ТЗ 3.7)

`src/transfer/ur.c` входит в хостовую сборку, поэтому проверяемо без
железа:

- bytewords minimal: кодирование/декодирование round-trip, эталонные
  векторы Blockchain Commons;
- `mw_ur_crc32` против известных значений;
- фонтанный кодек: закодировать полезную нагрузку, скормить части декодеру
  в перемешанном порядке, с пропусками и дубликатами, проверить сборку;
- `mw_ur_decoder_receive` возвращает `MW_ERR_FORMAT` на мусоре и не портит
  внутреннее состояние;
- `mw_ur_encoder_is_single_part` для нагрузки меньше фрагмента.

## 3. Что НЕЛЬЗЯ проверить на хосте

Ничего из этого списка хостовый набор не покрывает и покрыть не может:

| Область | Почему | Как проверять |
| :--- | :--- | :--- |
| **Дисплей** | нужна панель и SPI | вручную на плате; правильность цветов, отсутствие сдвига, отсутствие тиринга |
| **Тач** | нужен контроллер по I²C/SPI | вручную; попадание по 40×40 элементам (ТЗ 4.1), калибровка резистивного |
| **Кнопки и энкодер** | GPIO | вручную; дребезг, длинное и очень длинное нажатие «Назад» (ТЗ 5.6) |
| **USB (MSC/MTP/Floppy/Composite)** | нужен TinyUSB и хост-система | вручную на Windows, macOS, Linux |
| **SCSI Unit Attention** | поведение кэша конкретной ОС | вручную, только Windows показывает проблему в полный рост |
| **Камера** | DVP-интерфейс | вручную; распознавание QR при разном освещении |
| **SD-карта** | SDIO/SPI, FAT32, извлечение на ходу | вручную на ES3C28P и Touch-LCD-2: см. чек-лист раздела 4 |
| **eFuse / HMAC** | необратимая операция на реальном чипе | на отдельной плате, которую не жалко; `mw_secure_key_provision()` нельзя откатить |
| **Зашифрованный NVS** | часть ESP-IDF | на плате; отдельно проверить, что после перезагрузки кошельки читаются |
| **TRNG** | аппаратный | `mw_random_selftest()` на плате; на хосте источник подменён |
| **Производительность** | другой процессор | замеры на плате: FPS ≥ 20, отклик < 100 мс (ТЗ 4.1), время генерации Bulletproofs+ |
| **Расход памяти** | другая модель памяти | на плате: `heap_caps_get_free_size`, наибольший свободный блок PSRAM, high-water mark стеков задач |
| **Затирание секретов в реальной памяти** | нужен дамп RAM | на плате, отладчиком или дампом |
| **Разделение задач FreeRTOS** | нет FreeRTOS на хосте | на плате: отсутствие watchdog при подписи, живой UI во время счёта |

Отдельно: ASan на хосте ловит выход за границы буфера в парсерах — это
самый ценный автоматический результат, потому что парсеры обрабатывают
данные из недоверенного источника. Гоняйте `make asan` на каждом
изменении в `monero/serialize.c`, `monero/file_formats.c`,
`monero/tx.c` и `transfer/ur.c`.

## 4. Проверка на устройстве перед stagenet

Перед тем как идти в сеть, стоит убедиться в базовом:

- [ ] `mw_random_init()` возвращает `MW_RNG_OK`;
- [ ] `mw_random_selftest()` проходит после перезагрузки;
- [ ] `mw_cn_slow_hash_init()` возвращает 0;
- [ ] `mw_bpp_init()` возвращает `MW_OK`;

## 5. Процедура stagenet (ТЗ 13.6)

ТЗ 13.6 требует трёх вещей: подпись, broadcast, проверка принятия. Ниже —
развёрнутый чек-лист. **Пока он не пройден целиком, устройство не считается
работоспособным.**

### Подготовка

- [ ] Собрать прошивку с `MW_DEFAULT_NETWORK` = `MW_NET_STAGENET`
      (`src/config/app_config.h`) либо переключить сеть в настройках
      (`mw_settings_t.network`).
- [ ] Поднять `monerod --stagenet` или выбрать публичный удалённый узел
      stagenet.
- [ ] Установить Feather в режиме stagenet (и/или Monero GUI stagenet).
- [ ] Получить тестовые XMR из stagenet-крана.

### Шаг 1. Кошелёк

- [ ] Создать кошелёк **на устройстве** (не в Feather): TRNG или кубики.
- [ ] Записать seed-фразу.
- [ ] Задать passphrase — сначала прогнать сценарий **с пустым**
      passphrase (кнопка «Без passphrase» + подтверждение).
- [ ] Записать адрес, который показало устройство.
- [ ] Импортировать в Feather **view-only** кошелёк по адресу и view key
      либо восстановить по той же seed-фразе и сверить адрес.
- [ ] **Адреса должны совпасть.** Если нет — дальше идти нельзя.
- [ ] Повторить весь шаг для кошелька с **непустым** passphrase; проверить,
      что Feather (seed offset) и Monero CLI с той же фразой и тем же
      passphrase дают тот же адрес; пустой passphrase открывает второй
      кошелёк той же фразы.

### Шаг 2. Поступление

- [ ] Перевести тестовые XMR на адрес кошелька.
- [ ] Дождаться подтверждений.
- [ ] Feather видит поступление.

### Шаг 3. Синхронизация key images

- [ ] Feather: экспорт выходов в папку обмена `mwlink_gui.py`.
- [ ] Программа отправила файл (наблюдение за папкой и «Send file...»).
- [ ] Устройство приняло файл, показало прогресс, посчитало key images без
      ошибок.
- [ ] В папке появился `<кошелёк>_<время>_keyImages`.
- [ ] Feather: `Import key images` — **принял без ошибок**.
- [ ] Баланс в Feather верный.

### Шаг 4. Подпись транзакции

- [ ] Feather: создать перевод на другой stagenet-адрес.
- [ ] Сохранить неподписанную транзакцию в папку обмена.
- [ ] Передать на устройство.
- [ ] Устройство разобрало файл **без ошибки формата** — это главная
      проверка совместимости раскладки `unsigned_tx_set` v2.
- [ ] Экран подтверждения показывает **правильные** сумму, адрес
      получателя целиком и комиссию.
- [ ] Специально проверить: адрес на экране совпадает с тем, что был введён
      в Feather, символ в символ.
- [ ] Подтвердить, дождаться завершения. Зафиксировать время подписи.
- [ ] В папке появился `<время>_signed_monero_tx`; Feather его принял.

### Шаг 5. Broadcast и приём сетью

- [ ] Feather: загрузить подписанную транзакцию, `Submit transaction`.
- [ ] Узел **принял** транзакцию (нет `Failed to parse`, нет
      `tx verification failed`).
- [ ] Транзакция появилась в mempool.
- [ ] Транзакция попала в блок.
- [ ] В обозревателе блоков stagenet видно, что транзакция подтверждена.
- [ ] Баланс отправителя уменьшился на сумму + комиссию.
- [ ] Получатель видит поступление.

### Шаг 6. Повторы и граничные случаи

- [ ] Ещё одна транзакция, чтобы проверить, что key images от первой
      правильно учтены (нет двойной траты).
- [ ] Транзакция с **двумя** получателями.
- [ ] Транзакция на **субадрес**.
- [ ] Транзакция без сдачи (отправить всё).
- [ ] Отмена на экране подтверждения — устройство возвращается в меню,
      ничего не подписав.
- [ ] Испорченная неподписанная транзакция (изменить байт) — отказ с
      `MW_ERR_SIGNATURE`, без падения.
- [ ] Файл от **другого** кошелька — отказ, без падения.
- [ ] Набор с **двумя** транзакциями — каждая показывается и подписывается.
- [ ] Транзакция на входе, чей key image не синхронизирован, — отказ с
      подсказкой.
- [ ] Запрос view-only данных: код на устройстве, JSON в папке, view-only
      кошелёк Feather видит баланс.
- [ ] Отключение питания посреди подписи — после включения устройство
      загружается, кошельки целы, ключей в памяти нет.
- [ ] Обе повторные попытки по QR: прерванное сканирование, кадры не по
      порядку.

### Шаг 7. Оба кошелька

- [ ] Повторить шаги 3–5 для кошелька **Polyseed**.
- [ ] Повторить для кошелька с **непустым passphrase**.
- [ ] Повторить через **Monero GUI** (обмен только файлами — QR он не
      поддерживает, ТЗ 3.7).

### Критерий прохождения

Все пункты шагов 1–7 отмечены, ни один не обойдён. Результаты (версия
прошивки, версии Feather/Monero GUI, хеши транзакций stagenet) записаны.
Только после этого имеет смысл разговор о mainnet — и то с минимальными
суммами.
