# Пароль устройства (task2, п. 1; ТЗ 2.0 §3.1, §3.6; аудит v6)

## Зачем

Ключ eFuse (ТЗ 8.1) защищает seed от чтения флеша на другом чипе. Он не
защищает от злоумышленника, который прошьёт в *этот* чип свою прошивку: она
может вызвать HMAC-периферию так же, как наша, и расшифровать NVS. Пароль
устройства закрывает эту дыру: без него ключ расшифровки не выводится.

## Схема (запись версии 2)

```
state_1 = PBKDF2-HMAC-SHA256(пароль, salt16 || "mw.device.pw.v2" || 0, R/8)
для i = 1..7:
    h_i     = eFuse-HMAC("mw.pw.hw" || i || state_i)
    state_i+1 = PBKDF2-HMAC-SHA256(state_i || h_i, salt16 || tag || i, R/8)
h      = eFuse-HMAC("mw.pw.hw.final" || 0 || state_8)
out    = HMAC-SHA512(h, state_8)
pw_key = out[0..32)          verifier = HMAC-SHA256(out[32..64), "mw.device.verify")

ключ записи = HMAC-SHA256(pw_key, hw_key || label),  hw_key = eFuse-HMAC(label)
```

R = `MW_DEVICE_PW_ROUNDS` = 200 000. Ключ eFuse участвует в выводе 8 раз.
Поэтому дамп NVS (вместе с verifier) нельзя перебирать на видеокарте: каждая
попытка требует этот чип, его скорость и проходит через счётчик попыток.

**Ключ eFuse обязателен (v8).** Проверка `efuse_gate()` в `mw_shell_run()`
идёт после игры и **до** запроса пароля: если ключа нет, устройство сразу
предлагает его прожечь (экран *Provision the eFuse key*), и без этого дальше не
пускает — ни задать пароль, ни создать кошелёк. Отладочного режима с
публичной константой больше нет: `mw_secure_hw_hmac()` без ключа возвращает
`MW_ERR_NOT_SUPPORTED`. Для ключа берётся самый старший свободный блок
(KEY5 и ниже) или уже прожжённый блок `HMAC_UP` с защитой от чтения; номер
хранится в NVS (`hw_kblk`), список блоков — *Settings → eFuse key blocks*.

Совместимость со старыми прошивками сохранена только на чтение:

- параметры пароля, созданные до прожига (флаг 0 не выставлен), выводятся с
  публичной константой и при первом входе переводятся на ключ eFuse;
- записи кошельков старого отладочного режима (аппаратная часть =
  keccak(метка)) открываются, `mw_secure_last_unseal_legacy()` сообщает об
  этом, и при обновлении записи пароля всё перешифровывается под eFuse.
  Новых записей так не создаётся.

**Скорость.** PBKDF2 считается с предвычисленными внутренним и внешним pad
HMAC (две компрессии SHA-256 на итерацию вместо четырёх), а на ESP32-S3 —
аппаратным ускорителем SHA после самопроверки при первом вызове (если
проверка не прошла, остаётся программная версия). Результат бит в бит тот
же, число раундов не уменьшено: быстрее стал только сам вычислитель, а не
перебор для злоумышленника — у него те же 200 000 раундов и 8 обращений к
eFuse этого чипа на каждую попытку.

Время разблокировки на ESP32-S3 **не измерено**. При включённом отладочном
логе (*Settings → Debug log*) по UART пишется строка
`[auth] password check took N ms`. Если выходит слишком долго, уменьшите
`MW_DEVICE_PW_ROUNDS` (новые записи создаются с новым значением, старые с
большим не понижаются).

## Пользователи (v9)

Паролей может быть несколько — по одному на пользователя (аккаунт; Настройки
→ *Add account*; подробно и про скрытность — `security.md` §4a, `user_guide.md` §2a).

- Соль и число раундов из записи `devauth` — **общие для всех**: любой пароль
  проходит тот же вывод и даёт ключ своего пользователя `K`. Поэтому вход
  стоит один вывод ключа при любом числе пользователей.
- Verifier записи принадлежит только **первому** пользователю. Любой другой
  пароль — пользователь, если в файловом хранилище есть открывающийся
  каталог `u` + 24 hex от `HMAC(K, "mw.user.dir.v1")`. Списка
  пользователей нет нигде.
- Смена пароля первого пользователя и обновление записи **сохраняют соль и
  число раундов** (от них зависят ключи остальных); число раундов записи
  версии 2 больше не повышается автоматически.
- Пароль другого пользователя меняется без записи `devauth`: каталог
  перешифровывается под новый ключ (`mw_wallet_store_rekey`, см. ниже).
- Счётчик неверных попыток и задержка — общие. Ответ «пароль занят»
  (`MW_ERR_EXISTS`) при добавлении пользователя или смене пароля считается
  неверной попыткой. Второй счётчик `fails_total` не даёт подбирать чужой
  пароль бесконечно, входя между попытками своим.
- Каталог первого пользователя помечен; если после смены его пароля
  остался старый каталог (сбой после точки фиксации), старый пароль не
  открывает его «другим пользователем» — вход новым паролем доводит смену.
- Удаление первого пользователя оставляет запись (с солью), но заменяет
  verifier случайными байтами.

### Смена пароля без записи `devauth`

Каталог пользователя — один запечатанный файл, поэтому смена атомарна так:

1. старый каталог помечается «заменён» и хранит новый ключ;
2. записи кошельков перешифровываются в памяти;
3. пишется новый каталог с пометкой «перенос» и старым ключом — **точка
   фиксации**;
4. кэши key images переносятся под новые имена и ключ;
5. старый каталог удаляется, новый переписывается без пометки.

Сбой до шага 3 оставляет всё под старым паролем. После шага 3 вход любым из
двух паролей заканчивает перенос (`mw_wallet_store_user_probe` /
`mw_wallet_store_resume`). Первый пользователь проходит тот же путь внутри
своей атомарной смены записи `devauth`.

## Требования к паролю

| Что | Значение |
| :--- | :--- |
| Длина любого нового пароля (первая настройка, смена, новый аккаунт) | от `MW_DEVICE_PW_MIN` = 8 до 64 символов; проверяет и интерфейс, и `device_auth.c` |
| Длина при входе | не проверяется: пароли из 4–7 символов, заданные до v7, по-прежнему открываются |
| Слабый пароль (`mw_device_pw_weak`) | только цифры, один повторяющийся символ, возрастающая или убывающая последовательность (`12345678`, `aaaaaaaa`, `hgfedcba`). Устройство предупреждает и просит подтвердить; запретить нельзя — решает владелец |

## Запись `devauth` (NVS, 177 байт; 175 до v9)

| Смещение | Поле |
| ---: | :--- |
| 0 | `"MWDA"` |
| 4 | версия записи (2) |
| 5 | раунды текущего пароля |
| 9 | salt (16) |
| 25 | verifier (32) |
| 57 | счётчик неудачных попыток |
| 58 | флаги: 0 — вывод с eFuse; 1 — идёт смена пароля; 2 — новый пароль с eFuse; 7 — текущие параметры ещё версии 1 |
| 59..174 | только во время смены: раунды, salt и verifier нового пароля; `wrap_new = new_key ^ HMAC(old_key, "wrap.new")`, `wrap_old = old_key ^ HMAC(new_key, "wrap.old")` |
| 175 | v9: `fails_total` — счётчик ошибок, который успешный вход не обнуляет: уменьшается на 1 только после 10 входов подряд без ошибок (повторная проверка пароля внутри сессии его не уменьшает); выше 6 даёт свою, удваивающуюся задержку |
| 176 | v9: `clean_streak` — входы подряд без ошибок |

Запись в 177 байт прошивки до v9 не читают: откат на них не поддерживается
(они сочтут запись повреждённой и предложат сброс).

Запись версии 1 (58 байт, 20 000 раундов SHA-512, без eFuse) по-прежнему
открывается и при первом успешном входе обновляется до версии 2.

## Свойства

| Что | Как |
| :--- | :--- |
| Счётчик попыток | увеличивается и **записывается до** проверки пароля, обнуляется после верного. Отключение питания по виду тока не сохраняет попытку. Первые две неудачи без задержки, дальше 2^(N-2) с, максимум 10 мин; перезагрузка задержку не сбрасывает |
| Пустой ввод | не попытка |
| Смена пароля | атомарна. 1) пишется запись «идёт смена» с параметрами нового пароля и обоими ключами, завёрнутыми друг в друга; 2) кошельки и кэши key images перешифровываются (`mw_wallet_store_rekey` можно запускать повторно); 3) запись нового пароля. Если питание пропало между 1 и 3, следующий вход принимает **любой** из двух паролей, достаёт второй ключ из обёртки, доводит перешифровку и завершает смену |
| Запись повреждена или пропала, а кошельки есть | `mw_device_auth_state() == MW_AUTH_CORRUPT`: новый пароль задать нельзя (он бы осиротил кошельки), устройство объясняет ситуацию и сразу предлагает сброс к заводским |
| Сбой не из-за пароля (нет eFuse, ошибка перешифровки) | попытка не засчитывается |

## Код

- `src/wallet/device_auth.h/.c` — запись, KDF, проверка, задержка, смена, восстановление,
  пользователи (`mw_device_auth_add_user`, `_delete_user`, `_check`).
- `src/wallet/wallet_store.c` — каталоги пользователей, пустышки, перенос старого
  каталога из NVS, атомарная перешифровка.
- `src/wallet/secure_storage.{h,cpp}`, `secure_storage_host.c` — `mw_secure_hw_hmac()`,
  хранение `pw_key` и его подмешивание в ключ записи.
- `src/wallet/wallet_store.c` — `mw_wallet_store_rekey()` (идемпотентна), `mw_wallet_store_count()`.
- `src/ui/flows.cpp` — `device_auth()`, `screen_settings.cpp` — смена пароля.
- `src/crypto/hmac_pbkdf2.c` — PBKDF2 с предвычисленными pad, путь через
  ускоритель SHA и его самопроверка.
- Тест: `tools/test/test_device_auth.c`: прерванная смена в обоих местах и
  с обоими паролями, привязка к ключу чипа, обновление записи версии 1,
  привязка после прожига eFuse, повреждённая и пропавшая запись, сбои записи
  и чтения NVS, слабые пароли; `test_users.c` — пользователи; `test_wallet_store.c` — чтение записей
  старого отладочного режима; `test_hash.c` — векторы PBKDF2.

## Что не сделано

  есть, но кнопки/таймера выключения пока нет.
- Пароль вводится текстовой клавиатурой и виден на экране во время ввода.
