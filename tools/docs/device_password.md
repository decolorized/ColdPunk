# Пароль устройства (task2, п. 1; ТЗ 2.0 §3.1, §3.6; аудит v6)

## Зачем

Ключ eFuse (ТЗ 8.1) защищает seed от чтения флеша на другом чипе. Он не
защищает от злоумышленника, который прошьёт в *этот* чип свою прошивку: она
может вызвать HMAC-периферию так же, как наша, и расшифровать NVS. Пароль
устройства закрывает эту дыру: без него ключ расшифровки не выводится.

## Схема (запись версии 2)

```
state_1 = PBKDF2-HMAC-SHA256(пароль, salt16 || "mw.device.pw.v2" || 0, R/8)
для i = 1..7:
    h_i     = eFuse-HMAC("mw.pw.hw" || i || state_i)
    state_i+1 = PBKDF2-HMAC-SHA256(state_i || h_i, salt16 || tag || i, R/8)
h      = eFuse-HMAC("mw.pw.hw.final" || 0 || state_8)
out    = HMAC-SHA512(h, state_8)
pw_key = out[0..32)          verifier = HMAC-SHA256(out[32..64), "mw.device.verify")

ключ записи = HMAC-SHA256(pw_key, hw_key || label),  hw_key = eFuse-HMAC(label)
```

R = `MW_DEVICE_PW_ROUNDS` = 200 000. Ключ eFuse участвует в выводе 8 раз.
Поэтому дамп NVS (вместе с verifier) нельзя перебирать на видеокарте: каждая
попытка требует этот чип, его скорость и проходит через счётчик попыток.

Пока ключ eFuse не прожжён, вместо него используется публичная константа
(отладочный режим, как у меток записей). При первой разблокировке после
прожига запись автоматически переводится на ключ eFuse.

Время разблокировки на ESP32-S3 **не измерено**. В отладочном логе по UART
пишется строка `[auth] password check took N ms`. Если выходит слишком долго,
уменьшите `MW_DEVICE_PW_ROUNDS` (новые записи создаются с новым значением,
старые с большим не понижаются).

## Запись `devauth` (NVS, 175 байт)

| Смещение | Поле |
| ---: | :--- |
| 0 | `"MWDA"` |
| 4 | версия записи (2) |
| 5 | раунды текущего пароля |
| 9 | salt (16) |
| 25 | verifier (32) |
| 57 | счётчик неудачных попыток |
| 58 | флаги: 0 — вывод с eFuse; 1 — идёт смена пароля; 2 — новый пароль с eFuse; 7 — текущие параметры ещё версии 1 |
| 59..174 | только во время смены: раунды, salt и verifier нового пароля; `wrap_new = new_key ^ HMAC(old_key, "wrap.new")`, `wrap_old = old_key ^ HMAC(new_key, "wrap.old")` |

Запись версии 1 (58 байт, 20 000 раундов SHA-512, без eFuse) по-прежнему
открывается и при первом успешном входе обновляется до версии 2.

## Свойства

| Что | Как |
| :--- | :--- |
| Счётчик попыток | увеличивается и **записывается до** проверки пароля, обнуляется после верного. Отключение питания по виду тока не сохраняет попытку. Первые две неудачи без задержки, дальше 2^(N-2) с, максимум 10 мин; перезагрузка задержку не сбрасывает |
| Пустой ввод | не попытка |
| Смена пароля | атомарна. 1) пишется запись «идёт смена» с параметрами нового пароля и обоими ключами, завёрнутыми друг в друга; 2) кошельки и кэши key images перешифровываются (`mw_wallet_store_rekey` можно запускать повторно); 3) запись нового пароля. Если питание пропало между 1 и 3, следующий вход принимает **любой** из двух паролей, достаёт второй ключ из обёртки, доводит перешифровку и завершает смену |
| Запись повреждена или пропала, а кошельки есть | `mw_device_auth_state() == MW_AUTH_CORRUPT`: новый пароль задать нельзя (он бы осиротил кошельки), устройство объясняет ситуацию и сразу предлагает сброс к заводским |
| Сбой не из-за пароля (нет eFuse, ошибка перешифровки) | попытка не засчитывается |

## Код

- `src/wallet/device_auth.h/.c` — запись, KDF, проверка, задержка, смена, восстановление.
- `src/wallet/secure_storage.{h,cpp}`, `secure_storage_host.c` — `mw_secure_hw_hmac()`,
  хранение `pw_key` и его подмешивание в ключ записи.
- `src/wallet/wallet_store.c` — `mw_wallet_store_rekey()` (идемпотентна), `mw_wallet_store_count()`.
- `src/ui/flows.cpp` — `device_auth()`, `screen_settings.cpp` — смена пароля.
- Тест: `tools/test/test_device_auth.c`: прерванная смена в обоих местах и
  с обоими паролями, привязка к ключу чипа, обновление записи версии 1,
  привязка после прожига eFuse, повреждённая и пропавшая запись, сбои записи
  и чтения NVS.
