# Пароль устройства (task2, п. 1; ТЗ 2.0 §3.1, §3.6)

## Зачем

Ключ eFuse (ТЗ 8.1) защищает seed от чтения флеша на другом чипе. Он не
защищает от злоумышленника, который прошьёт в *этот* чип свою прошивку: она
может вызвать HMAC-периферию так же, как наша, и расшифровать NVS. Пароль
устройства закрывает эту дыру: без него ключ расшифровки не выводится.

## Схема

```
pw_key || verify_key = PBKDF2-HMAC-SHA512(пароль, salt16 || "mw.device.pw.v1", 20000)
verifier             = HMAC-SHA256(verify_key, "mw.device.verify")

ключ записи          = HMAC-SHA256(pw_key, hw_key || label)
                       hw_key = eFuse-HMAC(label)  (или keccak(label) без eFuse - отладочный режим)
```

- В NVS хранятся `salt`, `verifier`, число раундов и счётчик неудачных
  попыток (`devauth`, 58 байт). `pw_key` в NVS не попадает никогда.
- `pw_key` живёт во внутренней SRAM (`DRAM_ATTR`) на всё время работы и
  подставляется в `mw_seal()/mw_unseal()` через `mw_secure_user_key_set()`.
  Без него любое запечатывание и распечатывание возвращает
  `MW_ERR_NOT_SUPPORTED`.
- Стойкость: PBKDF2 на 20000 раундов SHA-512 — порядка 0,3–0,5 с на
  ESP32-S3 (оценка, не измерено). Подбор офлайн по дампу NVS ограничен только
  этим; поэтому пароль от 4 символов — минимум, рекомендуется длиннее.

## Поведение

| Ситуация | Что видит пользователь |
| :--- | :--- |
| Первое включение | «Задайте пароль устройства», ввод дважды, затем главное меню |
| Обычное включение | «Введите пароль устройства»; пока не введён — никакие операции недоступны |
| Неверный пароль | «Неверный пароль (попытка N)». Первые две — без задержки. Любая непустая строка считается попыткой |
| Пустой ввод | «Пароль не введён»; попыткой не считается |
| 3 и более неудач | задержка 2^(N-2) с, максимум 10 мин; счётчик хранится в NVS, перезагрузка не сбрасывает задержку |
| Верный пароль | счётчик обнуляется в RAM и в NVS. Сброс пишется, если счётчик не ноль в RAM **или в NVS**; если запись не удалась, вход всё равно открывается, ошибка один раз пишется в лог, а запись повторяется при следующей проверке пароля и при блокировке (`mw_device_auth_save_pending()`). Неудачная запись увеличения счётчика повторяется так же |
| После входа | если с прошлого входа были неудачные попытки — сообщение «Неудачных попыток с последнего входа: N» |
| Смена пароля | Настройки → «Сменить пароль устройства». Во время задержки сразу показывается «Слишком много попыток» и возврат в настройки. Старый пароль проверяется сразу после ввода (верный обнуляет счётчик, даже если смену потом отменить); затем новый дважды, при несовпадении или длине вне 4..64 спрашивается только новый. Все кошельки перешифровываются одной транзакцией (`mw_wallet_store_rekey`); запись, которая не расшифровалась при перешифровке, — `MW_ERR_FORMAT`, а не «неверный пароль» |
| Сброс устройства | запись `devauth` стирается вместе с NVS |

## Код

- `src/wallet/device_auth.h/.c` — запись, KDF, проверка, задержка, смена.
- `src/wallet/secure_storage.{h,cpp}`, `secure_storage_host.c` — хранение
  `pw_key` и его подмешивание в ключ записи.
- `src/wallet/wallet_store.c` — `mw_wallet_store_rekey()`.
- `src/ui/flows.cpp` — `mw_flow_device_auth()` (вызывается криптозадачей до
  всего остального), `screen_settings.cpp` — смена пароля.
- Тест: `test/test_device_auth.c` (в том числе сбои записи и чтения NVS через
  `mw_host_store_fail_writes()` / `mw_host_store_fail_reads()` из
  `secure_storage_host.c`).

## Что не сделано

- Zeroization ключа при выключении (ТЗ 2.0 §3.6): `mw_device_auth_forget()`
  есть, но кнопки/таймера выключения пока нет.
- Пароль вводится текстовой клавиатурой и виден на экране во время ввода,
  как и passphrase (ТЗ 2.0 §3.2). Маскирование можно включить тем же
  флагом, что и у числовой клавиатуры.
