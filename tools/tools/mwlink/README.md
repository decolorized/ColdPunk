# mwlink — программа на ПК для Monero Cold Wallet

Курьер между Feather Wallet и устройством по USB (Serial или HID, протокол
2 — `docs/usb_link_protocol.md`). Программа переносит файлы и показывает
журнал устройства; всё, что связано с ключами, делает устройство и только
после подтверждения на его экране.

```
pip install pyserial hidapi
python mwlink_gui.py          # окно
python mwlink.py --help       # командная строка
```

## Окно (`mwlink_gui.py`)

1. **Connect** — устройство ищется по VID/PID: сначала HID (нужен `hidapi`),
   затем COM-порт. Порт можно выбрать вручную (порты не кошелька помечены
   «not a wallet»); если выбранный порт занят другой программой (Arduino IDE
   Serial Monitor, второй экземпляр mwlink), окно подключится по HID. В журнале
   видно, как подключились: «connected over hid» / «connected over serial
   COMx», и причина последнего сброса устройства («last reset: ...»).
   Если устройство перезагрузилось или кабель выдернули, окно пишет «device
   disconnected» и само переподключается, как только устройство появится.
   Результаты, которые устройство успело сделать до сброса, потеряны —
   отправьте файл ещё раз.
2. **Folder** — папка обмена с Feather (по умолчанию `exchange` рядом с
   программой).
3. **Watch the folder** — файлы, которые Feather сохранил в папку (экспорт
   выходов, неподписанная транзакция), отправляются сами; отправленный файл
   переносится в `sent/` (если Feather ещё держит файл открытым, он остаётся
   на месте, и это видно в журнале; второй раз он не отправляется).
   Остальные файлы в папке не трогаются.
4. **Send file...** — отправить любой файл: устройство само определит по
   содержимому, что это, и объяснит, если файл ему не подходит. Выбранный
   вручную файл не переносится и наблюдением повторно не отправляется.
   Кнопки отправки и запросов доступны только при подключённом устройстве;
   под ними написано, если нужно открыть кошелёк на устройстве или
   устройство ещё занято предыдущим файлом.
5. **Request address / Request view-only wallet data** — запрос адреса или
   данных для view-only кошелька (адрес + private view key). Устройство
   показывает запрос; view key уходит только после ввода кода на устройстве.
6. Результаты сохраняются, как только устройство их сделало: рядом с
   отправленным файлом (файлы из наблюдаемой папки и данные кошелька — в
   папку обмена), с именами в стиле Feather:

   | Вход | Результат |
   | :--- | :--- |
   | `borya-view2_1789637203_outputs` | `borya-view2_1789638364_keyImages` |
   | `1789839233_unsigned_monero_tx` | `1789839961_signed_monero_tx` |
   | запрос view-only | `borya_1789839990_viewonly.json` |

   Если файл отклонён на устройстве, в журнале будет «no result for ...».
   Private view key показывается в отдельном окне (кнопка «Copy view key»)
   и в журнал не пишется.
7. **Device log** — что делает устройство, отказы с причинами, в отладочном
   режиме устройства — подробности. «Save log...» сохраняет журнал.

## Командная строка (`mwlink.py`)

| Команда | Что делает |
| :--- | :--- |
| `info`, `status` | версия, состояние устройства, открытый кошелёк, очереди |
| `send FILE [--out DIR]` | отправить любой файл и дождаться результата |
| `request address\|viewonly [--out DIR]` | запросить данные кошелька |
| `exchange [DIR]` | наблюдать за папкой, как окно |
| `console` | только журнал устройства |
| `put [KIND\|auto] FILE`, `get KIND OUT`, `clear [KIND]` | низкоуровневые команды |

Транспорт: без флагов — HID, если он есть, иначе COM-порт по VID/PID;
`--hid` — только HID; `--serial PORT` — этот порт, а если он занят — HID.
Прошивка, собранная с `MW_USE_SERIAL 0` (профиль `coldpunk-hid`), по COM-порту
не отвечает — используйте HID; с `MW_USE_HID 0` — наоборот, только `--serial`
(см. `tools/docs/build_arduino.md` §2a).
`info` показывает и причину последнего сброса (`last reset`), а для
разблокированного устройства после сбоя — на каком этапе он случился. Если
во время команды устройство перезагрузилось («read error»), программа ждёт
его до 10 с и печатает причину сброса.

## Тесты без устройства

`link_sim.c` — имитатор устройства: настоящее ядро протокола (`link.c`) и
распознавание файлов прошивки, отвечающее без экрана и подтверждений.

```
gcc -std=c11 -O2 -DMW_HOST_BUILD=1 -IMoneroColdWallet/src tools/mwlink/link_sim.c ^
    MoneroColdWallet/src/transfer/link.c MoneroColdWallet/src/monero/*.c ^
    MoneroColdWallet/src/crypto/*.c MoneroColdWallet/src/hal/hal_host.c ^
    MoneroColdWallet/src/hal/log.c MoneroColdWallet/src/data/*.c -o link_sim
python tools/mwlink/test_mwlink.py link_sim.exe
python -B tools/mwlink/test_mwlink_gui.py link_sim.exe
```

`link_sim` понимает `--locked`, `--confirm-ms N` (файл «на экране» N мс,
состояние busy), `--decline N` (первые N файлов отклонены пользователем) и
`--crash` (INFO сообщает сбой при подписи). `test_mwlink_gui.py` запускает
настоящее окно без экрана: поддельный tkinter лежит в `tests/faketk`,
поддельные pyserial/hidapi — в `tests/simdev.py`; tkinter, pyserial и hidapi
для тестов не нужны.

(`^` — перенос строки в cmd.exe; в bash — `\`.)
